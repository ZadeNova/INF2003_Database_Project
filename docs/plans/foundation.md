# foundation: Roles, MongoDB, docs consolidation

status: done
owner and implementer: Erfan · estimate: 1.5 to 2 days · phase 0 (21 to 25 October)

## Contract

**Goal.** A clean local-only baseline that runs on Linux and Windows with PostgreSQL and MongoDB in Compose, real
least-privilege roles, a small set of docs, and a docs check that runs before every commit. No feature or
schema work.

**In scope**

| Area | Change |
|---|---|
| Settings | One configuration with today's local values: plain HTTP, no SSL redirect, cookies not marked secure, no HSTS, no proxy header, `DEBUG` off unless `DJANGO_DEBUG=true`. |
| Database connection | `src/config/database.py` |
| PostgreSQL roles (decision g) | Two roles, created by the PostgreSQL init script: an **owner** that owns the database and runs `migrate`, the importer and pytest (which needs `CREATEDB`), and a **runtime** role for `web` with `CONNECT`, schema `USAGE`, `SELECT, INSERT, UPDATE, DELETE` on tables and `USAGE, SELECT` on sequences, granted through `ALTER DEFAULT PRIVILEGES FOR ROLE owner` so future tables are covered. The `migrate` service uses the owner's credentials, `web` the runtime's. |
| Compose | One root `compose.yaml` with `db`, `mongo`, `migrate`, `web`. The latest stable PostgreSQL and MongoDB releases (check the official release pages; do not assume), pinned by digest. For PostgreSQL 18 and later, check the image's data path when pinning: those images expect the volume at `/var/lib/postgresql`, and a volume at `/var/lib/postgresql/data` stops startup |
| MongoDB | Single-node replica set `rs0` with authentication. The keyfile is generated inside a container into a named volume (mode 400, owned by the mongodb user), never bind-mounted from the host, which fails on Windows. Start-up order: start `mongod` with `--replSet rs0 --keyFile`, run `rs.initiate` with host `mongo:27017`, then create the root user and the app user with `readWrite` on `mercer` and `test_mercer` only. Variables: `MONGO_ROOT_USER`, `MONGO_ROOT_PASSWORD`, `MONGO_APP_USER`, `MONGO_APP_PASSWORD`, `MONGO_DB`. The app connects with `replicaSet=rs0`; host-side tools need `directConnection=true`. Healthcheck on `rs.status()`. Add pinned `pymongo`; `check_database` reports both engines |
| `init_env.py` | Generates the secrets (owner and runtime passwords, the `MONGO_*` values) and **adds missing keys to an existing `.env`** |
| Analytics | Create `profile_olist.py`, `build_shoe_dataset.py` and `export_coverage.py` |
| Load harness (decision h) | `benchmark` writes a new local HTTP load script |
| Docs | `docs/DATA_MODEL.md`; Create `docs/DECISIONS.md`, `docs/AI_USE.md` and `CONTRIBUTIONS.md` |
| Docs check | `scripts/check_docs.py` (standard library only) and `.githooks/pre-commit` (tries `python3`, then `python`); add `.githooks/* text eol=lf` to `.gitattributes`. `.md` files outside the AGENTS.md list (allow-list `src/static/vendor/**` and `src/static/models/CREDITS.md` until the models go), unpaired generated-section markers or markers naming a missing script, plan files without a valid status (changed 21 October: plans are kept after close-out, so `status: done` is allowed), and README commands naming a missing script or Compose service. **Generated-section convention:** `<!-- generated by <script path> -->` … `<!-- end generated -->` |
| Packaging | `scripts/package_submission.py` |
| Misc | `.vscode/settings.json` with a cross-platform interpreter path |

**Out of scope:** Olist data, schema; CI (`ci`, phase 3); MongoDB collections and app code
beyond the connection and health check (`catalogue`).

**Tests**
- The suite passes, settings, database and request-logging tests.
- New: the runtime role can read and write table rows but is refused `CREATE TABLE`, `DROP TABLE` and `TRUNCATE`. The
  MongoDB app user can read and write `mercer` and `test_mercer` and is refused on any other database. `init_env.py`
  adds missing keys without changing existing ones. `check_docs.py` has a unit test per rule.
