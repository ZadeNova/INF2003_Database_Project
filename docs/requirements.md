# Requirements

## Rubric (verbatim)

Mark allocation: Project proposal 10%, Presentation (video+ppt) 25%, Final report
25%, Project quality & implementation 40%. Bands: Excellent >=80, Good 60-79,
Average 40-59, Fail <40. Project = 50% of module grade (25% relational + 25%
non-relational), final mark weighted by peer review.

Tasks:
A. Identify an application using both a relational and a non-relational database —
   either the same functionality on both, or split by function.
B. Identify datasets — real-world preferred, more datasets preferred, same or
   different subsets allowed per database.
C. Design: ER diagram with varied relationship types (1-to-many, many-to-1,
   many-to-many) and varied data types for the relational side; schema and data
   model specified in writing for the NoSQL side.
D. Implement: database construction plus common CRUD functions; encouraged to add
   complex functions demonstrating course concepts.
E. Analysis and reflection: performance analysis (speed, throughput), discussion of
   problems and potential improvements.

Deliverables: progress report (max 2 pages, Calibri Body 12) due Oct 4, 11:30pm;
final report (max 10 pages, same font, XSite template) + slides (.pptx) + video
(.mp4, max 10 min, penalties at 11-15/16-20/31+ min) + source code + user manual,
all due Nov 29, 11:30pm as one zip (or GitHub link if >2GB with access granted).
Every team member must present in the video; name on screen. Late = -20%/day/
deliverable. Peer review surveys required from all five members.

Extra credit for innovative ideas, advanced tech/UI, and appropriate use of advanced
SQL/NoSQL/DBMS features — complex queries, aggregates, nested queries, views,
non-standard integrity constraints, data analytics algorithms.
